# [설계] 전달된 셸의 사용자 회수·소유권 전환과 개입 요청

## 배경
현재 전달은 되돌릴 수 없고 AgentOwned 셸에는 사용자가 입력할 수 없다. 사용자가 직접 개입해야 할 때 새 SSH 연결만 만드는 방식이 충분한지 검토한다.

## 목표
사용자 회수, 사용자↔에이전트 소유권 전환, 에이전트의 개입 요청/알림 중 필요한 흐름을 정의한다. 같은 셸에 두 주체가 동시에 입력하지 않는 원칙은 유지한다.

## 검토할 사항
- 사용자 주도 회수와 에이전트 주도 요청을 구분한다. 팝업은 후보이며 구현 방식으로 확정하지 않는다.
- 실행 중 명령, 처리 중·대기 중 입력, VT 자동 응답, 모델의 후속 호출을 전환 경계에서 어떻게 다룰지 정한다.
- 소유권 변경 전 입력은 새 소유권에서 뒤늦게 실행되지 않아야 한다.
- 사용자 개입 중 출력의 MCP 공개 여부, 재전달 시 새 공개 스트림/커서 정의를 정한다.
- sudo 사용자 인증 경로와 일반 셸 회수가 같은 기능인지 분리된 기능인지 결정한다.

## 완료 기준
- 상태 전이표와 두 주체의 입력 권한표를 작성한다.
- 전환 중 단절·취소·실패·중복 요청의 처리와 회귀 검증 계획을 제시한다.
- 기존 ‘전달 후 회수 불가’ 계약의 변경 범위를 명시한다.
