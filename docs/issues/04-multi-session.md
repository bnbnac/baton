# [요구사항] 여러 셸·여러 MCP 연결의 사용 범위와 독립성 정의

## 배경
여러 종류의 셸 접근, 한 작업의 여러 셸 접근, 여러 독립 작업의 셸 접근이라는 서로 다른 요구가 아직 섞여 있다. 현재는 MCP 연결 하나당 셸 하나이며, 실제 시험에서는 같은 이름의 별도 연결에 셸을 전달해 상태가 다르게 보이는 일이 발생했다.

## 확정된 방향
여러 독립 작업/대화에서 사용하는 셸은 서로 독립되어야 한다. 모델이 임의로 제출하는 대화 ID만으로 소유권을 판단하지 않는다. 하네스의 연결 공유 여부를 검증해야 한다.

## 아직 결정하지 않은 범위
- ‘여러 종류’가 서로 다른 서버/계정/환경인지 bash·zsh 같은 로그인 셸 종류인지 구분한다.
- 한 대화에서 여러 셸이 필요한지, 여러 대화에 각각 한 셸이면 되는지 사례로 정한다.
- 로컬 셸 지원은 현재 요구로 확정하지 않는다. 기존 로컬 fallback 금지를 유지한다.
- 연결 생성/종료/재개/분기와 셸 배정의 관계를 정의한다.

## 완료 기준
- 대표 사용 사례와 범위 밖 항목을 정리한다.
- 한 작업의 복수 셸과 여러 작업의 독립 셸을 구분한 소유권 모델을 제시한다.
- 목록에서 대상 서버·계정·연결 ID·배정 상태를 구별하고, 자동 선택에 따른 오배정을 줄이는 방식을 제시한다.
- 다른 연결의 session_id를 넣어도 조회/입력이 차단되고, 한 연결 종료가 다른 연결의 셸에 영향을 주지 않는 검증 기준을 유지한다.
- Desktop/CLI 동시 시험은 별도 착수 지시 전까지 보류한다.
