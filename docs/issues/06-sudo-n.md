# [버그] sudo 승인 요청에서 -n이 누락되는 지침 수정

## 재현과 관찰
Claude Desktop에 /root의 총 디스크 사용량 확인이라는 목표만 요청하면 sudo 실행 전에 승인을 요청하지만, 제시한 명령이 ‘sudo du -sh /root’였다. 사용자 보정 후 ‘sudo -n du -sh /root’로 바뀌었고, 새 세션에서도 누락이 반복됐다.

## 원인 후보와 영향
AgentPolicy.Sudo에 ‘Only after approval, advise using the noninteractive sudo -n form’이라는 순서상 모호한 문구가 있다. 반면 승인된 텍스트만 보내고 -n을 자동 추가하지 말라는 지침도 있어, 승인 전 최종 명령을 구성하는 순서를 명확히 해야 한다. 문구가 모델 동작을 유발한 유일한 원인이라고 단정하지 않는다.

## 기대 동작
- 현재 비대화형 sudo 정책에서는 -n을 포함한 실제 최종 명령·모든 인자·목적을 승인 전에 제시한다.
- 승인받은 명령만 1회 실행한다. 승인 후 옵션을 자동 추가하거나 재작성하지 않는다.
- 새 실행/실패 후 재시도는 다시 승인받는다.
- 인증 실패를 캐시 부재나 만료로 단정하지 않는다. NOPASSWD 등 인증이 필요 없는 조건과 구분한다.

## 완료 기준
- 서버 instructions, 도구 설명, 사용자 안내의 승인 순서가 일치한다.
- 목표만 제시한 실제 하네스 시험에서 사용자 보정 없이 최종 비대화형 명령으로 승인을 요청하는지 확인한다.
- 비밀번호 대리 입력, 자동 자격 갱신, sudoers 변경은 추가하지 않는다.
- 문자열 필터나 강제 승인 엔진을 이 수정에 포함하지 않는다.
