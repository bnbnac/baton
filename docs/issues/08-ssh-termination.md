# [검토] Baton 종료 시 서버 세션 동작을 일반 SSH 클라이언트와 비교

## 목표
Baton 종료 시 원격 SSH 세션/셸/작업이 어떻게 되는지 명확히 한다. 일반 SSH 클라이언트와 동등하게 동작한다면 추가 강제 종료 기능을 만들 필요는 없다는 사용자 방향을 따른다.

## 현재 근거
- 사용자 실제 시험: Baton 종료 후 Claude에 Server disconnected. 이는 MCP 단절의 증거이며 서버 PID 종료의 증거는 아니다.
- 격리 OpenSSH/Bash 시험: 실제 Baton.Core 정상 정리 및 코어 호스트 강제 종료에서 해당 SSH 세션 프로세스·로그인 셸·일반 전경/백그라운드 작업 소멸.
- nohup+disown 작업은 두 조건에서 생존.
- 실제 WPF 배포 앱과 일반 SSH 클라이언트를 동일 서버 조건에서 비교한 PID 관찰은 미수행.

## 검토 범위
동일 서버·셸·명령으로 Baton과 일반 OpenSSH 클라이언트의 정상 종료/강제 종료를 비교한다. 연결 종료, 셸 종료, 모든 원격 작업 종료를 별개로 기록한다. 서버 OS나 전체 sshd 서비스 종료를 목표로 하지 않는다.

## 완료 기준
- 관찰용 독립 접속에서 PID/시작 시각/PTY 기준으로 결과를 기록한다.
- 일반 foreground/background와 터미널에서 분리한 작업을 구분한다.
- 정상 소켓 종료와 네트워크 blackhole을 동일하게 취급하지 않는다.
- 동등하면 문서화로 종료하고, 다르면 재현 가능한 차이만 별도 버그로 분리한다.
- 원격 일괄 kill이나 작업 rollback 기능은 추가하지 않는다.

관련: docs/testing/2026-09-16-acceptance-report.md, scripts/test-server-lifecycle.ps1.
우선 상태: 기존 검토 있음, 직접 비교 검증 미완료. 실행 착수는 별도 결정한다.
