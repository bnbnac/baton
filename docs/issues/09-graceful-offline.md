# [설계] Baton 종료·재시작을 MCP 연결 상태로 안내하는 수명 구조

## 배경
현재 어댑터는 Baton IPC가 끊기면 종료된다. Baton을 끄면 Claude에 MCP 서버 단절 경고가 표시되어, 예상된 앱 종료가 서버 장애처럼 보인다.

## 목표
Baton 창, SSH를 소유한 실행 프로세스, MCP 어댑터의 수명을 구분하고 정상적인 종료/오프라인 상태를 사용자에게 설명하는 방법을 설계한다.

## 비교할 선택지
- 어댑터는 유지하고 status에서 app_offline 등 명시적인 상태를 제공.
- 창 닫기를 백그라운드/트레이 전환과 구분하고, 완전 종료를 별도 제공.
- 현재 강한 수명 결합을 유지하되 종료 동작·오류 안내를 개선.
창을 숨기는 것과 SSH 소유 프로세스를 실제로 종료하는 것은 별개다. 하네스의 경고 표시를 Baton이 모두 제어할 수 있다고 가정하지 않는다.

## 계약
- 앱 프로세스가 종료되면 기존 SSH 세션의 종료 계약을 유지한다.
- 앱 재실행 시 예전 셸·출력·대기 입력을 자동 복원/재전송하지 않는다.
- IPC 재접속을 채택하더라도 새 연결·미배정 상태와 사용자의 새 전달을 요구한다.
- 재시도 상한, 새 endpoint 인증, 어댑터 종료, 폐기된 세션 ID 및 전송 결과 불확실성을 다룬다.
- 일반 예상 종료와 실제 내부 오류를 구분한다.

## 완료 기준
- 앱 미실행/실행 중/종료/재실행 상태표와 도구별 응답 계약을 정한다.
- 실제 하네스에서 도구 가용성과 사용자 메시지를 검증하는 기준을 제시한다.
- 앱이 꺼진 동안 이전 세션 입력이 수행되지 않고 재실행 뒤에도 늦게 재생되지 않는다.
- 크로스플랫폼 방향과 백그라운드 실행 여부를 함께 검토하되, 상주 실행을 필수로 미리 확정하지 않는다.
