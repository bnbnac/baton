## 정리한 방향

- 원래 첫 메모는 소유권 전환과 화면 기록 유지라는 별도 문제이므로 둘로 분리했다.
- Windows/macOS/Linux 지원을 목표로 기술을 재평가한다. Rust는 사용자 관심을 고려한 후보이며 재작성을 확정하지 않았다.
- 복수 셸 사용 범위는 탐색 사항이다. 여러 독립 작업이 사용하는 셸의 독립성은 유지한다.
- sudo UX는 쉬운 방식인 기존 하네스 대화의 실행 승인과 sudo -n 흐름을 우선한다. 별도 비밀번호 입력 통로나 승인 팝업은 우선 범위에서 제외한다.
- 서버 종료 동작은 일반 SSH 클라이언트와 동등하다면 문서화로 마무리하고 불필요한 강제 종료 기능을 추가하지 않는다.

## 검토 순서

1. 현재 정책의 결함인 -n 누락은 별도로 작게 수정할 수 있다.
2. 복수 셸 요구와 연결 식별, 간단한 sudo 승인 흐름을 정리한다.
3. 크로스플랫폼 기술 결정을 검토하고 UI 관련 변경의 구현 기반을 정한다.
4. 소유권 전환·과거 화면 유지·PTY resize·오프라인 처리는 각 경계의 상호작용을 설계한다.
5. 일반 SSH 클라이언트와 종료 동작 비교는 제품 개선 필요성을 판단하는 검증으로 취급한다.

이 순서는 구현 승인이나 일정 확정이 아니다. 각 본문의 범위와 완료 기준을 검토한 뒤 착수한다.
