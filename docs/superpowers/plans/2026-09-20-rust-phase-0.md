# Baton Rust Phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** russh 인증·PTY, rmcp stdio 수명, Tauri/xterm의 입력·자동 응답 분리가 승인된 구조를 지원하는지 격리된 실험으로 판정한다.

**Architecture:** C# MVP를 유지하고 `rust/experiments/`에 버릴 수 있는 작은 실행 파일과 시험 UI를 만든다. 실제 SSH, 실제 stdio 자식 프로세스, 실제 WebView의 관찰 결과를 모으며 제품 세션 코어와 사용자 환경 설정에는 연결하지 않는다. 통과한 라이브러리 버전과 경계 계약을 다음 단계 계획의 입력으로 사용한다.

**Tech Stack:** Rust stable/MSVC, Tokio, serde, russh, rmcp, Tauri 2, TypeScript/Vite, xterm.js/FitAddon, Node 내장 test runner, 격리 OpenSSH 컨테이너와 ssh2 합성 fixture. 정확한 버전은 첫 사용 시 공개 릴리스에서 확인하고 lockfile 및 보고서에 고정한다.

**Spec:** [승인된 구조](../specs/2026-09-20-rust-transition-design.md), [승인된 검증 기준](../specs/2026-09-20-rust-verification-design.md).

상태: 실행 전 계획. 체크박스는 모두 미수행이다. 사용자 설계 승인과 구현 계획 승인을 구분한다.

2026-09-21 후속 기록: 이 문서의 체크박스는 최초 계획 기록이며 현재 실행 증거는 [단계 0 보고서](../../testing/rust-phase-0-report.md)를 따른다. 단계별 진행 조건은 아래 정정 및 [단계 1 계획](2026-09-21-rust-phase-1-core.md)을 따른다. 남은 실제 UI 조작·WebView 하위 프로세스 종료 검증은 단계 2의 필수 완료 조건으로 이관한다. 단계 0 runner의 blocked/종료 코드 2는 유지하며, 이를 SDK 독립 코어 계획·구현의 선행 조건으로 요구하지 않는다.

## Global Constraints

- Windows 먼저 검증·배포하고 macOS/Linux는 해당 OS에서 실제 검증한 뒤 순차 지원한다.
- Rust 코어는 Tauri와 rmcp 타입에 의존하지 않는다. 실험 간 공유 타입도 SDK 타입을 외부 인터페이스로 내보내지 않는다.
- 셸마다 독립 SSH 연결을 사용한다. 로컬 셸 fallback, 외부 ssh로 transport 대체, 사용자 서버 접속, 하네스 설정 변경은 하지 않는다.
- 연결 / SSH 세션: 앱당 32 / 16.
- 일반 입력: UTF-8 16 KiB, 셸별 대기 32건.
- 요청 중복 이력: 셸·control_epoch별 4096건, 소진 시 새 입력 거부. 자동 회수로 초기화하지 않음.
- 공개 출력: 셸당 1 Mi UTF-16 단위, 조회 2–32768단위.
- 읽기 대기: 0–10000ms, 연결당 대기 read 최대 8개.
- IPC: frame 256 KiB, 연결당 진행 요청 16개.
- UI scrollback: 셸당 최대 1000행.
- UI 미확인 출력: 셸당 코어 1 MiB, xterm으로 한 번에 넘기는 미확인 바이트 64 KiB.
- 개입 이유: UTF-8 2 KiB, 제어문자 거부.
- 프로토콜 조회: 셸당 미처리 32개, 생성 후 2초 만료, 응답 최대 128바이트.
- epoch·cursor·sequence: 0부터 2^53−1 범위의 정수. 상한 초과 증가 시 명시적 종료, 순환 금지.
- 전환 장벽 5초, 앱 정상 종료 정리 최대 5초. 원격 명령 완료를 기다리거나 자동 Ctrl+C를 보내지 않는다.
- PTY 초기 120×32, 열 20–500, 행 5–200. resize 최대 100ms에 한 번, 같은 값 생략, 숨김/최소화 시 마지막 유효 크기 유지.
- 오프라인 재접속: 1초, 2초, 4초 후 최대 5초 간격과 작은 지터. 한 번의 연결·인증 시도 3초 제한.
- 인증정보·터미널 원문·원문 예외는 파일/진단 로그에 저장하지 않는다. 합성 시험 표식과 수치만 증거로 남긴다.
- C# `src/`, `tests/`, `build.cmd`를 덮어쓰지 않는다. 기존 C# 시험 결과를 Rust 통과로 계산하지 않는다.
- 제품 기능은 단계 1 이후에 구현한다. 이 계획의 probe가 통과해도 33개 인수 기준 전체를 충족한 것으로 표시하지 않는다.

```ts
type SshCase = 'password-pty' | 'host-reject' | 'host-cancel'
```

`ssh-probe`는 stdin의 한 JSON 입력으로 `{case, host, port, hostFingerprint, credential}`을 받고 결과 코드를 JSON 한 줄로 반환한다. fixture만 `127.0.0.1`에 bind하고 probe도 단계 0에는 loopback 주소만 받는다. credential은 실행별 시험 값이며 command line, 환경변수, 보고서에 넣지 않는다. 진행 중 취소는 다음 stdin 줄 `{"cancel":true}`로 전달한다. 이는 시험 제어 프로토콜이며 제품 인증 API가 아니다.

`ssh.mjs`는 부모 프로세스 전용 IPC 메시지로 ready/hostFingerprint/auth-stage/shell/received/resize/closed를 알린다. stdout의 포트 숫자만으로 준비를 추정하지 않는다. 인증 장벽은 부모의 release 메시지가 올 때까지 응답을 보류한다. 실패는 test runner에 전파하며 catch 후 성공으로 바꾸지 않는다.

- [ ] **Step 3: russh 직접 연결과 호스트키 확인→인증→PTY→shell 순서를 구현한다.**

`check_server_key`는 fixture가 별도 경로로 알려준 공개 지문과 비교한다. 항상 true를 반환하지 않는다. 서버의 shell 허용 이후 `ABC\r`을 한 번만 보내고 echo를 기다린다. 초기 PTY 120×32와 이후 91×27 window-change를 요청한다. 성공·실패 모두 channel/connection을 닫는다.

다음 순서를 유지한다. 각 내부 함수는 `pty.rs`에 구현한다.

```rust
// main.rs에서 호출하는 실험 내부 함수. SDK 타입은 이 경계 밖으로 내보내지 않는다.
async fn password_pty(input: ProbeInput) -> Result<(), ProbeError> {
    let mut ssh = connect_and_verify_host(&input).await?;
    authenticate_password(&mut ssh, &input).await?;
    let mut channel = open_pty_shell(&mut ssh, 120, 32).await?;
    send_and_observe_echo(&mut channel, b"ABC\r").await?;
    resize(&channel, 91, 27).await?;
    close_channel_and_connection(channel, ssh).await
}
```

`ProbeInput`은 stdin JSON의 역직렬화 타입, `ProbeError`는 `HostRejected/Cancelled/AuthFailed/TransportFailed/Timeout` enum이며 출력 시 snake_case 고정 코드로 변환한다. SDK 예외 원문을 stdout/stderr에 쓰지 않는다. 내부 함수의 SDK 타입은 채택한 release의 `client::Handle` / `Channel`로 정의한다. 모든 await는 시험 전체 10초 제한에 포함한다. 실패 시에도 연결을 drop하고 자식 프로세스 종료를 확인한다.

```js
const run = await runInjectedFailure('after-fixture-ready');
assert.notEqual(run.exitCode, 0);
assert.equal(run.createdProcessesStillRunning, 0);
assert.equal(run.createdContainersStillRunning, 0);
assert.equal(run.unrelatedSentinelStillRunning, true);
```

`runInjectedFailure(stage)`는 cleanup.test.mjs의 helper이며 위 고정 stage만 받는다. 시험이 별도의 sentinel 자식 프로세스도 만들어, 정리 후에도 살아 있는지 확인하고 마지막에 직접 종료한다. 기존 사용자 프로세스를 sentinel로 쓰지 않는다. container는 생성 당시 ID/name/고유 label을 모두 대조한다.

보고서 열은 `경계 / exact dependency version / command / OS-runtime / commit·lock hash / cases pass-fail-skip / evidence / decision`이다. 판정은 adopt/reject/blocked이며 russh·rmcp·Tauri/xterm을 각각 판정한다. blocked는 부족한 환경, reject는 재현 입력과 깨진 계약을 기록한다. stdout/stderr 전문을 첨부하지 않는다.

## 실행 중 리뷰와 학습

Task마다 실행 명령, 실패→성공의 변화, 채택 API, Rust의 타입/async/소유권 학습 내용을 짧게 보고한다. 제품 코드를 대량 작성한 뒤 마지막에 몰아서 시험하지 않는다. 독립 리뷰에서는 성공 메시지보다 server audit·stdio wire·Rust 수신 카운터를 확인한다.

이번 단계는 **Native**를 권장한다. 같은 구현자가 SDK를 조사하면서 작은 실험을 진행하고 마지막에 별도 리뷰어가 전체를 확인한다. Subagent-driven은 Task마다 구현과 리뷰를 분리한다. 학습 설명과 통과 조건은 동일하다.
