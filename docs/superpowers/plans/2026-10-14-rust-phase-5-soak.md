# Phase 5 2시간 부하 시험 실행 계획

> **For agentic workers:** Use superpowers:executing-plans. 승인된 검증 설계 §4의 실행이며 새 제품 기능은 추가하지 않는다.

**Goal:** 실제 Windows 제품 UI, MCP 32연결, 두 localhost OpenSSH 서버의 16개 셸로 7,200초 정상 소비 부하와 별도 과부하 종료를 검증한다.
**Architecture:** 검증된 lifecycle 실행 패턴을 새 실행기에 적용한다. 로그 생성·명령 기록은 시험 컨테이너 내부 fixture만 사용한다. 실제 UI에서 접속·탭 선택·회수·재전달하며 CDP는 시험 인스턴스에만 활성화한다.
**Tech Stack:** 기존 Node/Playwright/PowerShell Job 감독기/Docker OpenSSH, 기존 UI 및 최신 어댑터 바이너리.
**Spec:** `docs/superpowers/specs/2026-09-20-rust-verification-design.md` §4.

## 제약과 판정

- 실제 사용자 서버·인증·하네스 설정을 변경하지 않는다. 퍼징 작업은 포함하지 않는다.
- 두 컨테이너에 8개씩, 합계 16개 SSH 셸. 어댑터 32개를 유지하고 제어권을 앞/뒤 16개 연결 사이에 순환한다.
- 셸별 초당 최소 1KiB 구조화 로그와 30초마다 4KiB burst. 고유 세션 표식과 증가 번호로 데이터 혼합·역행·중복을 검사한다. 회수 후 새 공개 구간의 첫 불완전 라인은 허용하되 그 뒤 번호 연속성을 검사한다.
- 분당 모든 셸에 고유 audit 명령을 전송하며 같은 send_text request_id를 한 번 재전송한다. 종료 전 서버 audit 파일을 대조하여 명령 효과 중복·누락 0을 확인한다.
- 분당 탭 전환/터미널 크기 변경, 한 세션 회수·다른 어댑터에 재전달. 소유권 전환으로 숨겨지는 출력은 데이터 손실로 오판하지 않고 공개 구간별 검사한다.
- 30초마다 앱·Job 내 WebView·32어댑터의 private bytes와 working set을 합산한다. 20분 warm-up 제외, 이후 20분 구간별 중앙값을 기록한다. 두 지표 각각 마지막/첫 안정 구간 비율을 보고하고 1.2 초과 시 조사 전 통과시키지 않는다.
- 정상 부하 완료 후 별도로 32KiB를 0.1초 간격으로 40번(1.25MiB) 보내 정상 소비 대조를 먼저 확인한다. 대상 세션의 UI ack만 차단하고 같은 출력을 보내 명시적 세션 종료와 나머지 15개 세션 생존을 확인한다. 정상 부하 시간에 섞지 않는다. 내부 큐 상한의 정확한 수치는 기존 core 단위 검증과 구분한다.
- 실행 디렉터리는 신규 생성한다. `stop` 파일로 중단, summary로 상태 조회 가능. 중단·오류는 실패로 기록하고 정상 통과로 승격하지 않는다. 소유 fixture만 정리한다.
- 60초 사전 시험은 2시간 완료로 세지 않는다. 실제 7,200초는 16개 출력 준비 뒤부터 측정한다. 최종 코드 검토 뒤 실행 소스를 고정한다.
