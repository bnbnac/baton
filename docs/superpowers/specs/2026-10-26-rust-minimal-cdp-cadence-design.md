# 최소 CDP 전환 주기 진단

상태: 2026-10-26 사용자가 이 설계를 승인하고 구현 계획 작성을 요청했다. 실제 실행은 아직 시작하지 않았다. 구현 순서는 [구현 계획](../plans/2026-10-26-rust-minimal-cdp-cadence.md)을 따른다.

## 목적과 근거

기존 32연결/16세션/2서버에서 전환과 audit/health를 60초 안에 완료할 수 있는 조작 경로를 확인한다. 이번 변경은 기존 진단의 짧은 확장이며 제품 기능 개발이나 2시간 시험이 아니다.

[네이티브 주기 진단](../../testing/rust-native-cadence-feasibility.md)은 첫 회차 60.026초에 중단됐고 완료 회차는 0이었다. 도구 왕복과 보조 도구 오류가 포함됐으므로 제품 반응 지연이나 모든 네이티브 자동화의 불가능을 입증하지 않는다. 기존 M 고정 부하, F 전환, N 네이티브 조작 통과도 결합 전환 메모리를 입증하지 않는다.

[메모리 조사](../../testing/rust-phase-5-memory-investigation.md)의 짧은 Network OFF/ON/OFF 진단에서는 Network만의 뚜렷한 대규모 보유 증가를 확인하지 못했다. 자동화 연결 없는 실행이 안정됐다는 관측은 있지만 통제 조건이 달랐다. 따라서 Network를 끈 CDP도 메모리에 영향이 없다고 가정하지 않는다.

## 검토한 방법

- **선택: 최소 raw CDP로 화면 요소 조작.** 모델의 회차별 개입 없이 실행기가 진행한다. Playwright의 추가 도메인 활성화를 피할 수 있지만 CDP 연결과 JS 실행 자체는 계측 개입이다.
- 네이티브 보조 도구와 운영 절차 개선: 실제 입력 경로를 유지하지만 이전 오류 수정만으로 분당 실행 가능성이 증명되지는 않는다. 이번에는 반복하지 않는다.
- 결합 시험 유예: 실행 비용은 줄지만 미검증 범위가 남는다. 사용자는 최소 CDP 검토를 선택했다.

## 조작 범위 — 구현자 제안

1. 기존 고정 바이너리와 보존 image를 재사용한다. 공통 소스·바이너리·환경을 기존 M/F 기준과 대조하고 추가 진단 소스는 별도 해시로 기록한다. 준비용 Playwright는 측정 전에 완전히 분리한다.
2. 이번 실행 소유 앱의 loopback 디버깅 endpoint와 정확한 page target을 확인한 뒤 raw CDP 연결 하나만 사용한다. 다른 앱/탭으로 대체하지 않는다. 측정 전 Network.disable 응답을 기록하고 Network/Runtime/Debugger/HeapProfiler 등의 도메인 enable, 네트워크 본문 수집, heap/JS 메모리 조회, 강제 GC는 하지 않는다.
3. DOM에서 대상이 정확히 하나이고 표시·활성 상태인지 확인한 뒤 버튼 click과 select의 value/change 이벤트로 기존 화면 핸들러를 실행한다. 전체 세션 ID와 연결 ID를 대조한다. Tauri invoke, 내부 ownership 모델, backend 함수를 직접 호출하지 않는다. 합성 DOM 조작이므로 실제 마우스·키보드·포커스 검증으로 주장하지 않는다.
4. 크기 변경은 기존 F처럼 `.terminal-workspace`의 너비를 720/1000px 사이에서 바꾼다. 두 값이 실제 geometry 차이를 만들지 못하면 실패한다. 실제 OS 창 최대화/복원과는 다른 시험이며 기존 N 증거를 대체하지 않는다. 정상 GeometryObserver→PTY 경로와 서버 `stty size` 일치를 확인한다.
5. 회차별로 세션 **0→1→0**을 선택하고 크기 변경→회수→현재 owner의 반대 연결 선택→전달을 수행한다. 선택 직후 geometry 안정 750ms, user_owned/epoch 증가, 새 owner/stream, 이전 owner 해제를 MCP로 독립 확인한다. 화면의 성공 반환만으로 통과시키지 않는다.
6. CDP 표현식은 작고 동기적인 DOM 조작·필요한 ID 조회만 허용한다. 앱에 비동기 반복 루프·타이머·영구 helper를 삽입하지 않는다. 원격 객체 핸들을 보유하지 않고 작은 값을 반환한다. 각 CDP 요청/응답의 시간, 메서드, 표현식 해시 및 결과를 제한된 크기로 기록한다. 출력 payload나 인증 정보를 수집하지 않는다.

## 시간, 부하, 중단

최대 3회이며 회차 시작부터 상태 검증·전체16세션 audit·전체32연결 health까지 60초 상한을 유지한다. 다음 시작은 이전 시작+60초보다 빠르지 않다. 준비 포함 900초 상한, 정상 종료/정리 시간 별도, 첫 실패 즉시 후속 회차 중단을 유지한다. 밀린 회차 몰아 실행·기한 연장·자동 재시도는 금지한다.

CDP 연결은 준비 후 짧은 측정 전체에 하나를 유지한다. 회차 사이 재연결을 반복하지 않는다. 요청 시간 제한은 회차/전체 잔여 시간 이내로 제한하고 오류·연결 종료·대상 소멸은 실패로 처리한다. 시간 초과는 이미 전달한 입력의 취소나 미실행을 뜻하지 않는다. 후속 입력을 막고 진행 중 작업과 부분 효과를 기록한 뒤 기존 정상 종료 절차를 수행한다.

출력 부하·stream 내 연속성/격리·audit 효과 검증은 유지한다. 승인된 즉시 회수 계약에 따라 회수 시 미수신 공개 꼬리 폐기는 허용한다. 회수 후 이전 owner의 접근 차단은 별개로 검증한다.

OS 메모리는 30초 간격으로 기록하고 기존 표본 간격 검사를 유지한다. 디버깅 연결은 존재하므로 기존 M의 established=0 조건을 재사용하지 않는다. 소유 debugger 연결 관측, CDP 연결 시작/종료 및 명령 이력을 함께 남긴다. 이벤트가 없다는 사실만으로 Network 추적 부재를 증명했다고 하지 않는다.

## 증거와 판정

새 진단 경로와 별도 판정 파일을 사용한다. 기존 M/F/N 및 네이티브 주기 결과와 verifier는 변경하지 않는다. 공통 fixture/MCP/출력/소유 자원 정리를 재사용하되 UI 조작과 계측 계약은 별도다. 기존 raw CDP 구현은 참고 자료이며 timeout·종료·증거 수집을 그대로 충족한다고 가정하지 않는다.

독립 판정기는 원시 CDP/전환/MCP/audit/서버 geometry/출력/메모리/종료 기록을 대조한다. CDP 응답 성공과 실제 전환 성공을 구별하고 전체 세션 ID, 현재 binding 사슬, 요청 순서 및 부분 실패를 검증한다. 기록 누락은 증거 무효이며, 완전히 기록된 기한 초과는 유효한 부정 결과일 수 있다.

판정은 `evidenceValid`, `completedRounds`, `cadenceObserved`, `longRunReadiness: unproven`, `memoryAcceptance: not_evaluated`, `phase5Acceptance: false`로 구분한다. 3회 모두 검증 완료와 정상 종료·어댑터 EOF32·소유 잔류0이 있어야 cadenceObserved가 참이다. 짧은 메모리 수치에 2시간 판정을 적용하지 않는다. 증거 디렉터리와 검증 결과는 독점 생성하고 자동 재실행/덮어쓰기는 하지 않는다.

## 제외 범위와 다음 결정

제품·Cargo·미완성 fuzz를 수정/실행하지 않는다. 보존 image를 임의 삭제하지 않는다. 정리는 이번 owner label+이름/ID 및 PID+시작 시각이 일치하는 자원만 대상으로 한다. 기존 Phase5 출시 차단과 결합 전환 메모리 미검증은 유지한다.

이 문서 승인 다음 단계는 구현 계획이다. 실제 실행 전 구현과 필요한 검증을 마친다. 짧은 시험이 통과해도 2시간 시험은 자동 시작하지 않는다. 장시간 단계에서는 동일 환경의 최소 CDP 고정 화면 대조와 전환 조건을 별도로 설계해야 한다. 이전 detached M을 같은 계측 조건의 대조군으로 취급하거나 CDP 영향을 수치로 빼서 제품 메모리 통과를 만들지 않는다.
