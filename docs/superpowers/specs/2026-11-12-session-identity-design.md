# 세션 식별과 셸 소유 설계

작성일: 2026-11-12 · 관련 이슈: #18(설계 결정 기록), #19(후속 화면), #16(관측), #4(독립성 요구)

상태: 설계 초안. 사용자 승인 전에는 구현하지 않는다. 표기: **[결정]** 사용자가 대화에서 정한 것, **[제안]** 작성자(Claude)의 판단으로 사용자 확인이 필요한 것.

## 1. 의도와 배경

사용자는 Claude 세션 여러 개를 동시에 쓰면서 세션마다 SSH 셸을 따로 갖고 싶다. 대표 장면: 세션 A는 셸 A′·A″, 세션 B는 B′, 세션 C는 C′·C″·C‴를 쓴다. 같은 서버에 붙은 셸이어도 셸 자체는 별개이고, 한 셸은 한 세션만 제어한다.

현재 Baton에서 셸의 소유자는 **어댑터 연결**(`ConnectionId`)이다. Claude Desktop은 어댑터 프로세스를 세션마다 띄우지 않고 클라이언트 종류당 하나만 띄워 모든 Code 세션이 공유한다(#16 실험 1~4). 초기화·도구 호출 메시지 어디에도 호출한 세션을 알려 주는 값이 없다. 그 결과 (1) 세션들이 같은 셸 목록을 보고 서로의 셸을 쓸 수 있고, (2) 연결 이름이 마지막 호출로 덮어써져 핸드오프 목록에서 세션을 구별할 수 없다.

사용자는 CLI를 쓰지 않으며, Baton이 하네스 협조에 의존하지 않기를 원한다. 그래서 세션이 자기 식별자를 모든 호출에 실어 보내는 방식으로 푼다.

## 2. 목표 / 비목표 / 반목표

목표
- 셸의 소유자를 어댑터 연결이 아니라 **Claude 세션**으로 바꾼다. 한 세션이 셸 여러 개를 가질 수 있다.
- 한 세션의 `status`는 자기 셸만 보여 주고, 다른 세션의 `session_id`로 읽기·쓰기를 시도하면 거부한다.
- 핸드오프 목록과 이름이 세션 단위로 나온다 (이름 덮어쓰기 해소).
- 하네스, OS, 도구에 의존하지 않는다.

비목표
- 보안 격리. 신뢰 기반 격리(협조적인 에이전트의 혼동·사고 방지)가 목표다. 다른 세션이 식별자를 알아내 쓰는 경우, 셸 출력에 심어진 지시에 속은 에이전트의 오용은 막지 않는다.
- 하네스가 쓰는 세션 기록 파일로 호출을 검증하는 것 (1차에서 제외, 호환은 유지).
- 세션 종료 감지와 셸 자동 종료.
- 왼쪽 목록을 Claude 세션별로 묶는 화면 (#19).

반목표 (이것이 생기면 실패)
- 에이전트가 키를 실수로 빠뜨릴 때 다른 세션의 셸이 노출되는 것. 키가 없거나 틀린 호출은 항상 거부(실패하되 안전)한다.
- 앱이 대화 기록을 읽는 구조. 이 설계는 기록 파일을 읽지 않는다.

## 3. 제약

- 세션 정보는 하네스가 주지 않는다. 식별자는 세션 자신이 보낸다.
- 어댑터는 세션 여럿이 공유하는 프로세스 하나다. 시작 시점의 환경변수나 작업 디렉터리로는 세션을 구별할 수 없다.
- 호출 인자는 도구 스키마에 정의된 칸만 모델이 채울 수 있다. 식별자 칸을 스키마에 추가해야 한다.
- 기존 방어선은 유지한다: sudo 실행별 사전 승인, 사용자 직접 인증과 명시적 전달, 전달 후 사용자 입력 차단, 연결당 요청 한도. 연결 한도(32)와 동시 SSH 셸 한도(16)는 그대로 둔다.
- Windows 전용 기능이다 (기존과 동일).

## 4. 결정 사항

**[결정]**
1. 식별자는 **세션 UUID**이고 세션이 **모든 호출**에 싣는다. 앱은 셸과 이름을 이 값에 묶는다.
2. **위조를 막지 않는다.** 1차는 호출이 해당 세션의 기록에 있는지 대조하지 않는다.
3. 한 세션이 **셸 여러 개**를 갖는다. 같은 서버의 셸도 별개이며 셸 ID로 구별한다. 한 셸은 한 세션만 소유한다.
4. 셸 지목은 **세션의 판단에 맡긴다.** 새 계약 필드를 만들지 않고 기존 `session_id`, `label`, `target`을 쓴다.
5. 세션이 끝나도 셸이 **자동으로 종료되지 않아도 된다.** 셸은 세션 UUID에 묶인 채 남고 사용자가 앱에서 정리한다. 같은 UUID로 세션이 다시 열리면 그 셸을 다시 쓸 수 있다 (기존 `conversation-isolation-design.md`의 "재개된 대화가 이전 셸을 되찾지 않는다" 원칙을 바꾸는 결정).
6. **서브에이전트는 부모와 같은 키를 쓰는 것을 허용한다.** 한 세션 안에서 도는 서브에이전트는 별도 세션이 아니라 같은 세션 UUID에 속하므로(관측: 서브에이전트 기록의 `sessionId`가 부모 세션 UUID와 같고 `agentId`만 따로 있다) 같은 키는 같은 세션으로 취급한다. 별도로 시작한 Claude 세션(포크, 새 세션)은 자기 UUID를 가지므로 별개의 키다. Baton은 호출에서 서브에이전트와 부모를 구별할 수 없고, 금지는 지침으로만 가능하며 코드로 강제할 수 없다.
7. 연결 한도는 **32 그대로** 가상 연결에 적용한다. 부족하면 상향한다. 세션 아카이브·복원·재개 시 UUID 유지 여부는 이번 범위에서 고려하지 않는다.
8. 화면은 1차에 **A안**: 소유권 패널의 드롭다운만 "Claude 세션 선택"으로 바꾼다(항목: 제목 + UUID 앞 6자리). 화면 라벨의 "세션"은 **"셸"**로 바꾼다.

## 5. 설계

### 5.1 식별자 (`agent_key`) [제안: 세부]

- 세션 UUID(표준 8-4-4-4-12 표기)를 128비트 값으로 정규화한 것을 `agent_key`로 쓴다. 대소문자·하이픈 표기 차이는 정규화로 흡수한다.
- 세션은 환경 정보의 임시 폴더 경로(`...\claude\<id>\<세션 UUID>\scratchpad`)에서 자기 UUID를 읽는다. 이는 Claude Desktop에서 관측된 사실이고 계약으로 보장되지 않는다(관측: 이 값은 세션 기록 파일 이름과 같다). 경로에서 읽을 수 없는 하네스는 무작위 UUID를 만들어 세션 내내 같은 값을 쓴다 (폴백).
- 키는 비밀이 아니다. 다른 세션이 세션 목록 도구 등으로 알 수 있다.

### 5.2 MCP 계약 v3 [제안]

- 모든 도구(`status`, `set_connection_name`, `read_output`, `send_text`, `send_key`, `request_user_control`)에 필수 필드 `agent_key`(문자열, UUID)를 추가한다.
- `contract_version`을 3으로 올린다. 앱과 어댑터는 같은 빌드끼리 쓴다(기존 규칙). v2 어댑터와 v3 앱의 조합은 명확한 오류로 거부한다.
- 키가 없거나 형식이 틀린 호출은 `invalid_arguments`와 구별되는 오류 코드(예: `agent_key_required`)로 거부한다. 오류 문구에 키를 구하는 방법을 담아 에이전트가 스스로 고칠 수 있게 한다. 셸 목록은 돌려주지 않는다 (실패하되 안전).
- 어댑터는 키를 해석하지 않고 앱에 그대로 전달한다 (어댑터는 얇게 유지).
- `status` 응답에 이 키 기준의 셸만 담는다. `connection_id`는 응답에 남길지 설계 시 판단한다(진단용).

### 5.3 앱: 가상 연결로 코어 재사용 [제안]

현재 코어는 `session.assigned: Option<ConnectionId>`와 `Principal::Agent(ConnectionId)`로 소유와 권한을 판정한다. 이 구조를 바꾸지 않고, 앱의 에이전트 브리지(`agent_bridge.rs`)에서 호출의 `agent_key`를 **키에서 파생한 가상 `ConnectionId`**로 바꿔 코어에 넘긴다.

- 물리 연결(IPC 인증을 통과한 어댑터)은 계속 인증 단위이고 요청을 수신한다. 소유 판정에는 가상 연결 ID를 쓴다.
- 가상 연결은 해당 키의 **첫 유효 호출**에서 등록한다. `status`나 `set_connection_name`만 호출해도 등록되며, 그래서 Baton이 언급된 세션은 셸을 받기 전에 핸드오프 목록에 나타난다 (작성자 판단: 이것이 이 설계가 해결하려는 원래 문제다). 핸드오프 목록의 "MCP 연결"은 물리 연결이 아니라 가상 연결(= Claude 세션)을 나열한다.
- 연결 이름 저장소(`connection_names`)는 가상 연결 ID를 키로 쓴다. 이로써 덮어쓰기가 사라진다.
- 요청 한도, 읽기 대기 한도 같은 연결별 예산은 가상 연결 단위로 적용한다.
- 가상 연결 수는 기존 연결 한도(32)에 포함된다.

### 5.4 수명 [제안: 세부 규칙]

- 물리 연결이 끊겨도(어댑터 재시작, Desktop 재시작) 가상 연결과 거기에 묶인 셸은 그대로 남는다. 기존의 "연결 단절 시 셸 종료"는 가상 연결에는 적용하지 않는다. 사용자는 언제든 "내가 제어하기"로 회수할 수 있다.
- 처리 중이던 요청은 기존대로 취소하며, 입력 전송 중이던 경우 `uncertain` 의미를 유지한다.
- 가상 연결의 소멸: 앱 종료 시 모두 소멸(셸도 종료, 기존과 동일). 앱 실행 중에는 셸이 없는 가상 연결을 드롭다운에서 숨기는 기준(예: 마지막 호출 후 24시간)을 정한다 [제안, 값은 빌더 판단].
- 앱이 재시작하면 가상 연결과 셸이 모두 사라진다 (기존과 동일). 이후 세션이 같은 키로 다시 호출하면 새 가상 연결이 만들어진다.

### 5.5 화면 [결정 + 제안]

- 소유권 패널: 드롭다운 "MCP 연결 선택" → "Claude 세션 선택". 항목 라벨은 `제목 · UUID 앞 6자리`(기존 `connectionLabel`이 `이름 · id6` 형태). 제목은 세션이 `set_connection_name`으로 보낸 이름이고, 이름을 아직 보내지 않은 세션은 `Claude 세션 · UUID 앞 6자리`로 표시한다 (작성자 판단).
- 화면 용어: 왼쪽 목록 제목과 `세션 <id>`, `세션 ID 복사`의 "세션"을 "셸"로 바꾼다. Claude 세션은 "Claude 세션"으로 쓴다. 셸 ID는 현재처럼 12자리.
- 이미 어느 Claude 세션에 넘긴 셸은 다른 세션에 다시 넘길 수 없다 (기존 규칙: 사용자 제어 상태의 셸만 전달 가능).
- 목업 B(가진 셸 미리보기), C(Claude 세션별 목록)는 1차에서 제외한다.

### 5.6 지침 [제안]

- MCP `instructions`(`policy.rs`)와 `docs/agent-guide.md`에 추가: 모든 호출에 `agent_key`를 싣는다. 키는 환경 정보의 임시 폴더 경로에서 세션 UUID를 읽고, 없으면 무작위 UUID를 만들어 세션 내내 쓴다. Baton이 언급되면 먼저 `set_connection_name`으로 제목을 등록하고 `status`를 호출한다. 다른 세션의 키나 기록을 읽거나 쓰지 않는다. 키를 잃으면 같은 값을 다시 쓰고, 새 키를 만들면 기존 셸이 보이지 않는다는 점을 알려 준다.
- 지침은 권고이지 강제가 아니다.
- `docs/rust-personal-use.md`의 "어댑터는 세션마다 별도 프로세스" 문장은 사실과 달라 함께 고친다.

### 5.7 호환과 이전

- 앱·어댑터는 같은 빌드끼리 쓴다. 이전 에이전트(키를 안 보내는 지침)는 명확한 오류를 받는다. 키 없는 호출을 허용하는 호환 모드는 만들지 않는다 (격리가 무너지므로).

## 6. 위협 모델

| 상황 | 결과 |
|---|---|
| 협조적인 세션이 다른 세션의 셸을 자기 것으로 착각 | 막음 (키가 달라 목록에 안 보이고 호출 거부) |
| 서브에이전트가 부모의 키를 사용 | 허용 (결정 6). 같은 키 = 같은 세션 |
| 에이전트가 키를 빠뜨림 (컨텍스트 압축 등) | 호출 거부, 재시도 안내 |
| 다른 세션이 키를 알아내 사용 | 막지 못함 (비목표) |
| 셸 출력에 심어진 지시에 속은 에이전트의 오용 | 막지 못함. sudo 실행별 승인과 지침에 의존 |
| 같은 PC의 다른 프로세스가 IPC에 직접 접속 | 범위 밖 (기존 IPC 사용자 인증) |

## 7. 영향 범위 (확인된 위치)

- `rust/crates/baton-ipc/src/wire.rs`: `AgentRequest` 각 변형에 `agent_key` 추가, 검증, `StatusResult.contract_version`.
- `rust/crates/baton-adapter/src/tools.rs`, `policy.rs`: 도구 정의와 `parse`, `INSTRUCTIONS`.
- `rust/app/src-tauri/src/agent_bridge.rs`: `dispatch`/`commit_response`/`status`에서 물리 연결 대신 가상 연결 ID를 사용, `connected`/`disconnected` 수명 규칙.
- `rust/app/src-tauri/src/ownership.rs`: 연결 목록(`list_agent_connections`)과 이름 저장소.
- `rust/crates/baton-core`: 원칙적으로 변경 없음(가상 `ConnectionId` 재사용). 연결 한도와 `disconnect` 시맨틱 확인 필요.
- `rust/app/src/connections/view.ts`, `sessions/view.ts`, `main.ts`: 드롭다운 라벨과 "셸" 용어.
- 문서: `docs/agent-guide.md`, `docs/rust-personal-use.md`, 필요 시 `docs/conversation-isolation-design.md`의 갱신.
- 테스트: `crates/baton-adapter/tests`, `agent_bridge_tests.rs`, `rust/tests/*.mjs`의 계약 v2 가정.

## 8. 검증 기준

- 서로 다른 키의 두 호출자에서 `status`가 서로 다른 셸 집합을 돌려준다.
- 호출자 B가 A의 `session_id`로 `read_output`/`send_text`/`send_key`/`request_user_control`을 호출하면 거부되고 A의 셸 출력·입력이 변하지 않는다.
- 같은 물리 연결에서 서로 다른 키로 `set_connection_name`을 호출하면 두 이름이 따로 목록에 나온다.
- 키 없는 호출, 잘못된 형식의 키는 셸 정보 없이 거부된다.
- 물리 연결을 끊었다가 다시 붙여 같은 키로 호출하면 이전에 핸드오프한 셸이 남아 있다.
- 한 세션이 셸 3개를 가질 수 있고, 같은 서버의 셸이 서로 다른 ID로 구별된다.
- 기존 보호 장치(전달 후 사용자 입력 차단, 입력 취소·불확실 처리, 요청 한도, sudo 지침)의 기존 테스트가 통과한다.
- 화면에서 "Claude 세션 선택" 드롭다운으로 핸드오프하고 회수할 수 있다.

## 9. 열린 항목 (빌더 판단 또는 확인 필요)

- 셸이 없는 가상 연결을 목록에서 숨기는 기준값 (빌더 판단).
- 임시 폴더 경로에서 UUID를 읽는 것은 Desktop 관측에 의존한다. 다른 하네스에서의 취득 방법은 정하지 않는다 (폴백: 무작위 UUID).
- 도구 호출 기록 대조(위조 방지)의 도입 시점과 방식 (시점 측정, 서브에이전트 호출의 기록 위치 포함).

## 10. 빌더에게 남기는 것

- `agent_key`의 와이어 표기(하이픈 포함 36자 vs 32자 16진수)와 오류 코드 이름.
- 가상 `ConnectionId`의 파생 방법(키를 그대로 쓰는지, 해시하는지), 물리 연결과의 ID 충돌 방지.
- 물리 연결을 코어 레지스트리에 계속 등록할지 여부.
- 테스트 구성과 단계 분리(계약 → 앱 → 화면 → 문서).
