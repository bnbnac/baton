# Rust Phase 4 실제 하네스 확인

현재 **pending**이다. 자동 stdio 시험은 Claude/Codex의 화면 경고와 서버 유지 정책을 증명하지 않는다. 사용자가 설정한 단일 하네스에서 수행한다. 보류한 Desktop+CLI 동시 연결 시험은 포함하지 않는다.

준비: [Rust MCP 설정](../rust-harness-setup.md)의 어댑터를 사용하고 하네스 이름·버전을 기록한다. 기존 C# 도구와 구별한다. 테스트에 사용할 서버/계정은 사용자가 선택한다. 앱을 닫으면 앱이 소유한 SSH 세션들이 닫히므로 이 시험은 진행 중 작업이 없는 시험 세션에서 한다.

1. Rust Baton 앱을 끈 상태에서 해당 MCP 서버를 시작한다. 하네스에 다음을 요청한다.

   > Baton의 status만 호출해서 app_state, app_instance_id, connection_id, sessions를 그대로 보여줘. 셸 명령은 실행하지 마.

   초기화·도구 목록이 유지되고 status가 offline, ID null, sessions 빈 배열인지 기록한다. 하네스의 연결 경고가 있으면 정확한 문구도 기록한다. 경고가 없을 것이라고 미리 가정하지 않는다.
2. MCP 서버를 재시작하지 않고 Baton 앱을 켠다. 잠시 후 같은 status 요청을 보낸다. online, 새 연결 ID, 빈 세션이어야 한다. 앱/인증 상태에 따라 한 번 더 조회할 수 있지만 셸 명령을 재전송하지 않는다.
3. 앱에서 시험용 SSH 연결을 만들고 확인한 MCP 연결에 전달한다. `printf 'BATON_LIFETIME_TEST\n'` 한 번으로 명령·출력을 확인한다. 세션 ID와 연결 ID만 기록하고 비밀번호·개인 출력을 복사하지 않는다.
4. Baton 창을 정상 종료한다. 하네스와 MCP 서버는 유지한다. status가 offline·ID null·빈 세션이 되고 도구가 계속 조회 가능한지 확인한다. 기존 세션에 읽기나 입력을 시도하면 app_offline 오류여야 한다.
5. Baton을 다시 실행한다. status가 새 app_instance_id·새 connection_id·빈 세션으로 돌아오는지 확인한다. 예전 SSH나 명령이 자동 복원되면 실패다. 새 시험 셸을 연결하고 새 연결에 직접 전달한 뒤 명시적으로 새 명령을 요청한다.
6. 하네스의 해당 MCP 서버를 정상 중지한다. 어댑터가 종료되고 앱의 연결 선택 목록에서도 사라지는지 확인한다. 같은 연결이 에이전트 제어하던 셸은 닫히며, 사용자가 이미 회수한 셸은 유지돼야 한다.

결과에는 하네스 버전, 앱/어댑터 빌드 또는 hash, 각 단계의 상태, 경고 문구, 어댑터 종료 관측을 남긴다. 실패·미실시는 그대로 기록한다. 실제 모델 sudo는 [SUDO-01](rust-phase-3-manual.md)의 별도 시험이다.
