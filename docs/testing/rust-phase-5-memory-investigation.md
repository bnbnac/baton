# Phase 5 메모리 증가 조사

2026-10-14. [2시간 부하 시험](rust-phase-5-soak-report.md)의 메모리 기준 초과를 조사한다. **원인은 아직 확정하지 않았고 출시 차단을 유지한다.** 제품 코드·기존 시험 판정 기준은 변경하지 않았다.

**최신 상태 — 2026-10-15:** A/B 각 60분 비교 진단 및 최종 정리를 완료했다. 두 조건 모두 renderer 메모리가 증가했고 합산 private 증가율은 유사했다. UI 전환만을 원인으로 특정할 수 없으며, 공통 출력·명령·IPC·CDP/WebView 경로가 다음 조사 대상이다. 아래 준비/시작 문단은 당시 기록이며 최종 수치는 마지막 절을 따른다.

## 출력 부하와 CDP 연결 비교

증거는 `artifacts/phase5-memory-20261014/`에 보존했다. `make-probe.mjs`로 기존 soak 실행기의 진단용 복사본 `probe.mjs`를 만들었다. 릴리스 시험 실행기가 아니며 `probe1/summary.json`의 `diagnostic_completed`는 진단 절차 완료만 뜻한다.

- 기존 UI/어댑터 바이너리, MCP 32연결, SSH 16세션, localhost OpenSSH 컨테이너 2개.
- 각 셸에서 기존 구조화 로그와 burst를 지속 출력하고 MCP로 소비·검사했다.
- 약 120초 준비 → CDP 연결 유지 180초 → CDP 연결 해제 180초 → 재연결·최종 측정. 실제 측정 경과 **484.427초**.
- 측정 구간에서 resize·회수/재전달·명령 audit·과부하 시험은 제외했다. 따라서 원래 2시간 시험의 모든 동작을 재현하지 않는다.
- OS private bytes/working set, CDP JS heap·외부 저장소·embedder heap·DOM 수, Tauri callback 수를 관측했다. 경계에서 강제 GC를 적용해 회수 가능한 할당을 분리했다. GC를 제품 해결책이나 인수 조건으로 도입한 것이 아니다.
- PID와 시작 시각을 대조하고 명령행으로 이번 WebView **renderer PID 9712**를 확인했다. 이전 2시간 실행의 PID 46276 역할을 소급 확정하지 않는다.

## 결과

메모리 단위는 MiB다. JS heap과 renderer private는 서로 다른 지표이며 합산하지 않는다.

| 측정 시점 | 경과 초 | 강제 GC | JS heap | 외부 저장소 | Renderer private | DOM nodes | IPC callbacks |
|---|---:|---|---:|---:|---:|---:|---:|
| 준비 구간 종료 | 120.244 | 적용 | 8.94 | 19.75 | 131.84 | 1,793 | 17 |
| CDP 연결 유지 종료 | 301.350 | 적용 | 8.93 | 19.75 | 140.09 | 1,783 | 17 |
| 연결 해제 구간 후 재연결 | 482.581 | 미적용 | 54.95 | 19.75 | 209.08 | 3,188 | 17 |
| 최종 GC 후 | 483.480 | 적용 | 9.04 | 19.75 | 130.02 | 1,767 | 17 |

강제 GC 후 이벤트 리스너는 세 경계 모두 663개, 터미널은 16개였다. 마지막 GC 전후 renderer private는 약 **79.07MiB**, JS heap은 **45.91MiB** 감소했다. 이 출력 부하의 짧은 구간에서는 회수 가능한 할당이 메모리 변동의 상당 부분을 차지했다. 지속적으로 보유된 JS/DOM/IPC callback 수의 증가를 이 관측에서는 확인하지 못했다.

CDP를 해제한 구간에도 renderer private는 증가했다. 연결 유지가 유일한 원인이라는 해석은 지지하지 않는다. 반대로 짧은 순차 비교, GC 개입, 최종 재연결이 있으므로 계측의 영향을 완전히 배제하지도 않는다. GC 후 renderer가 처음 수준으로 돌아왔다고 해서 기존 2시간 실패를 정상 캐시나 누수 없음으로 재분류하지 않는다.

합산 private는 준비 후 GC 437.51 → 최종 GC 492.90MiB로 증가했다. 그중 Baton 앱은 31.89 → 80.15MiB였다. 이 진단은 초기 8분이므로 기존 20분 warm-up을 넘긴 안정 구간 비교가 아니다. 앱의 증가도 무시하지 않고 구간 길이와 버퍼 보유량을 별도로 확인해야 한다.

## 검증과 정리

`analyze-probe.mjs`가 `probe1/analysis.json`을 생성했다. 저장된 diagnostics/memory JSONL과 summary가 일치하고, 소스 9개·바이너리 2개 SHA256 및 진단 실행기 SHA256을 독립 대조했다. 진단 실행기 SHA256은 `19fd6dedd74fddac57a6f384b143e03010f1587417770d1e873a5e04c7d9cf28`이다. 사용한 바이너리는 기존 soak와 동일하며 최신 조합의 ZIP 재패키징을 뜻하지 않는다.

이번 진단에서는 앱 정상 종료, 강제 정리 없음, 관측한 WebView 자손 11개 종료를 확인했다. 실행기는 32개 어댑터 offline/EOF 종료와 stderr 없음도 검사했다. 컨테이너 2개를 소유 label·이름·ID 대조 후 제거했다. 후속 `cleanup-check.json`에서 표본의 PID·시작 시각 39개 중 살아 있는 시험 프로세스 0개, 소유 컨테이너 0개를 확인하고 ID가 일치하는 `baton-memory-20261014` 이미지 태그만 제거했다. 이 정상 종료 결과로 이전 2시간 실행의 미검증 종료 항목을 대체하지 않는다.
